# 1. Introduction

The DocsAI backend uses PostgreSQL as its primary relational database.

Instead of maintaining multiple databases for different workloads, DocsAI leverages PostgreSQL together with the pgvector extension, allowing both transactional data and AI vector embeddings to coexist within a single database.

This simplifies deployment while providing powerful capabilities for semantic search.

---

# 2. Why PostgreSQL?

PostgreSQL was selected because it provides:

- ACID compliance
- Excellent reliability
- Mature ecosystem
- JSON support
- Rich indexing
- Transaction support
- Extension support
- Native pgvector integration

This makes PostgreSQL suitable for both traditional application data and AI-powered retrieval.

---

# 3. Why pgvector?

Traditional databases compare text using keywords.

AI compares meaning.

pgvector stores embeddings as mathematical vectors, allowing similarity search using distance calculations.

Instead of asking:

> Does this sentence contain this word?

DocsAI asks:

> Does this sentence have the same meaning?

This is the foundation of Retrieval-Augmented Generation (RAG).

# 5. Documents Table

Purpose:

Stores metadata about uploaded documents.

Example information includes:

- Document ID
- File Name
- Object Storage Key
- MIME Type
- File Size
- Processing Status
- Upload Timestamp
- Created By
- Updated At

The actual file is **not stored** in PostgreSQL.

Instead, it resides in MinIO.

The database stores only metadata.

---

## Lifecycle

```

↓

Create Document Record

↓

Processing

↓

Ready

↓

Searchable
```

---

# 6. Document Chunks Table

Purpose:

Stores logical sections of a processed document.

After text extraction, a document is divided into multiple chunks.

Example:

```
Document

↓

Chapter 1

↓

Paragraph

↓

Chunk

↓

Database
```

Each chunk contains:

- Chunk ID
- Document ID
- Chunk Text
- Chunk Index
- Page Number
- Metadata
- Created Timestamp

Chunking improves retrieval quality by reducing context size.

---

## Why Chunking?

Large Language Models have context limits.

Instead of sending an entire document:

```
500 Pages
```

DocsAI retrieves only the most relevant chunks.

Benefits:

- Faster inference
- Lower token usage
- Better accuracy
- Reduced hallucinations

---

# 7. Document Embeddings Table

Purpose:

Stores vector embeddings for every chunk.

Each record contains:

- Embedding ID
- Document ID
- Chunk ID
- Embedding Model
- Vector
- Created Timestamp

The vector is generated by the AI Service and stored using pgvector.

---

# 10. Vector Storage

The vector column uses:

```
vector(1024)
```

Current embedding model:

- Ollama Embedding Model

Future models may include:

- Gemini Embeddings
- OpenAI Embeddings
- BGE
- E5
- Instructor
- Mixedbread
- Nomic

The model name is stored so embeddings remain traceable even if providers change.

# 11. Semantic Search

Current retrieval flow:

```
Question

↓

Generate Query Embedding

↓

Compare Against Stored Embeddings

↓

Rank Similarity

↓

Return Best Chunks
```

The backend retrieves the nearest vectors using pgvector similarity operators.

# 13. Why Separate Chunks and Embeddings?

Instead of storing vectors directly inside the chunk table, DocsAI separates them.

Advantages:

- Cleaner schema
- Easier model replacement
- Multiple embedding models
- Better versioning
- Future experimentation

This separation provides flexibility without affecting document data.

# 19. Database Philosophy

The DocsAI database is designed around a simple principle:

**Documents represent information. Chunks represent context. Embeddings represent meaning.**

Together, these three layers enable traditional data management while supporting modern AI-powered semantic retrieval.

---

# 20. Summary

The PostgreSQL database serves as the persistent foundation of DocsAI.

By combining relational data with pgvector embeddings, the platform can efficiently manage documents while enabling intelligent semantic search without introducing a separate vector database.

This architecture keeps deployment simple, maintains strong transactional guarantees, and provides a scalable foundation for the future evolution of DocsAI into a comprehensive AI Knowledge Platform.
